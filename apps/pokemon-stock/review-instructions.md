# Review 서브에이전트 지침: pokemon-stock

## 목표
Build 결과물을 독립적으로 검증한다. 브라우저에서 실제로 동작하는지, 코드와 데이터에 문제가 없는지 확인하고 `review.md`를 작성한다. 문제가 있으면 고친다. 너는 Build를 하지 않았으므로 Build 쪽 주장을 믿지 말고 직접 확인한다.

## 먼저 읽을 것
`/Users/hhnoh/프로젝트/샘플 블로그/apps/pokemon-stock/` 안의 `Spec.md`(0번 "확정 사항"이 우선), `build-instructions.md`, `index.html`, `style.css`, `script.js`, `data.json`.

## 수정 범위
- 만들 파일: 같은 폴더의 `review.md`
- 고칠 수 있는 파일: 같은 폴더의 `index.html`, `style.css`, `script.js`
- `data.json`은 형식 오류(깨진 JSON, 전화번호 포함 등)만 고칠 수 있다. 재고 값은 바꾸지 않는다.
- 그 외 파일은 건드리지 않는다. 재고조회 MCP 호출, 깃 명령, 배포, 설치, 서버 시작·중지는 하지 않는다.

## 브라우저 검증
미리보기 서버가 이미 떠 있다. `http://localhost:8765/apps/pokemon-stock/` 를 브라우저 도구(`mcp__Claude_Browser__*`)로 연다. 실제로 눌러서 확인한다.

1. 처음 화면: 제목, [재고 조회] 버튼, 안내 문구. 콘솔 오류 없음(`console.assert` 실패 포함).
2. 버튼 클릭 → 조회 기준 시각과 요약 카드 4개(CU, 이마트24, GS25, 세븐일레븐)가 나온다. 요약 숫자가 `data.json`에서 직접 센 값과 같은지 대조한다.
3. 요약 카드 클릭 → 아래에 점포 목록(점포명, 주소, 상품별 재고). 지역 필터가 동작한다. 점포가 없는 체인(GS25, 세븐일레븐)은 안내 문구가 나온다.
4. 점포 클릭 → 그 점포 바로 아래에 지도 `iframe`이 생기고, 지도가 실제로 그 점포 좌표 근처를 보여 준다. 다시 누르면 접힌다. "카카오맵에서 열기" 링크 주소가 올바르다(링크는 주소만 확인하고 열지 않아도 된다).
5. 모바일(375×812): 가로 스크롤 없음, 누르는 요소 높이 44px 이상, 글자가 잘리지 않음. 확인 후 뷰포트를 desktop으로 되돌린다.
6. 키보드: Tab으로 버튼·카드·점포에 도달하고 Enter/Space로 펼쳐지며, 포커스 표시가 보인다. `aria-expanded`가 상태에 맞게 바뀐다.
7. 재고 표시: 0은 "품절", `null`은 "확인불가", 숫자는 "재고 N". 색만으로 구분하지 않는다.
8. `data.json` 읽기 실패 시 오류 문구가 나오는지(코드로 확인해도 된다).

## 코드·데이터 검증
- 데이터를 `innerHTML`로 넣는 곳이 없는지, 외부 라이브러리를 쓰지 않는지.
- `data.json`: 유효한 JSON, 전화번호 없음, `stock` 값이 숫자 또는 `null`뿐, 좌표가 한국 범위 안, 점포 중복 없음, Spec 0번 구조와 일치.
- 입문자가 읽기 어려운 불필요하게 복잡한 코드, 쓰이지 않는 코드, 틀린 주석.
- 화면 문구가 사실과 맞는지(예: 이마트24는 반경 1km가 아니라 같은 구 안의 점포라는 점, 판교 이마트24는 조회 실패로 점포가 없다는 점이 방문자에게 정확히 전달되는지).
- 블로그로 돌아가는 링크가 동작하는지.

## 고칠 때
- 최소한으로 고친다. 기능을 새로 추가하지 않는다.
- 고친 뒤 해당 항목을 브라우저에서 다시 확인한다.
- 고치지 못했거나 사용자 결정이 필요한 문제는 고치지 말고 `review.md`에 남긴다.

## review.md 내용
한국어, 입문자가 읽을 수 있게 쓴다.
1. 결론 한 줄(통과 / 고쳐서 통과 / 문제 남음)
2. 확인 항목 표: 항목, 방법, 결과
3. 발견한 문제와 고친 내용(파일과 줄 번호)
4. 남은 문제와 사용자가 결정할 것
5. 확인하지 못한 것
