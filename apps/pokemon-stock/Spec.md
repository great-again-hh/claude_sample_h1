# Spec: 포켓몬 카드 편의점 재고조회 (pokemon-stock)

작성일: 2026-10-11 · 단계: 승인됨 (2026-10-11 사용자 승인, Build 진행)

## 0. 확정 사항 (사용자 결정)

아래 내용이 이 문서의 1번, 4번, 5번, 6번, 9번과 다르면 **이 항목이 우선**한다.

- **(2026-10-11 이후 변경, 아래 항목보다 우선)** [재고 조회] 버튼은 공개 재고조회 서버 `https://mcp.aka.page/`를 브라우저에서 직접 불러 **실시간으로 조회**하고 진행률을 %로 보여 준다(26회, 약 30초). `data.json`은 실시간 조회가 전부 실패했을 때만 쓰는 예비 결과다. 화면은 왼쪽 사이드바 + 오른쪽 본문의 독립 페이지이며 블로그와 서로 링크하지 않는다.
- **(2026-10-11 이후 변경, 아래 항목보다 우선)** 권역은 "구" 단위 7곳(서울 서초·강남·송파·중구, 수원 팔달·영통, 성남 분당)이며 왼쪽 사이드바의 체크박스로 고른다. 그 위의 편의점 체크박스(복수 선택)로 CU·GS25·세븐일레븐·이마트24 중 조회할 편의점을 고른다. 세븐일레븐은 점포 수만 센다. 조회할 상품은 사이드바의 입력칸에 직접 적으며(기본값 "포켓몬 카드"), 편의점마다 그 검색어로 찾은 첫 번째 상품의 재고를 조회하고 골라진 상품명을 요약 카드에 보여 준다. 점포 목록은 `stores.json`에 저장해 두고(`node build-stores.mjs`로 갱신), 체크한 권역의 점포만 조회한다. 결과에는 편의점별 대상 점포 수·재고 있음·품절·확인불가를 세어 보여 주고, 아래 목록에는 재고가 있는 점포만 나온다. 조회 1회가 10초 안에 응답하지 않으면 건너뛴다. `data.json`은 삭제했다.

- **조회 대상:** "포켓몬 카드"로 검색되는 카드 팩. CU 3종, 이마트24 2종을 최신 팩 위주로 Claude가 고른다.
- **조회 범위:** 안 B. 기준 지점 5곳(강남역, 홍대입구역, 서울역, 수원역, 판교역).
- **체인 표시:** 요약에 4개 체인을 모두 보여 준다.
  - CU: 재고 조회.
  - 이마트24: Build 전에 5회 이내로 추가 탐색해 빈 응답의 뜻을 확인한다. 끝내 알 수 없으면 재고를 `null`(확인불가)로 둔다.
  - GS25: 조회하지 않는다. "카드 팩 미취급"으로 표시한다(교통카드는 대상이 아니다).
  - 세븐일레븐: 복구 확인 1회. 실패하면 "조회 불가"로 표시한다.
  - 예상 호출: CU 15 + 이마트24 10 + 이마트24 탐색 최대 5 + 세븐일레븐 1 = 최대 31회 (세븐일레븐이 복구되면 11회 추가).
- **CU 재고 0 문제:** 확인함. 강남역 기준 생수(삼다수 500ml)를 조회하니 점포별 35~185개가 나왔다. 도구는 정상이며 포켓몬 카드의 0은 조회 시점의 실제 품절로 본다.
- **화면 흐름** (1번의 필터 목록과 6번의 그림을 대신한다):
  1. 처음에는 제목과 **[재고 조회] 버튼**만 보인다.
  2. 버튼을 누르면 `data.json`을 읽어 **조회 기준 시각**과 **편의점별 요약 카드 4개**를 위쪽에 보여 준다. 버튼은 저장된 결과를 불러올 뿐 실시간 조회가 아니며, 화면에 그렇게 적는다.
  3. 요약 카드를 누르면 그 아래에 해당 체인의 **점포 목록**(점포명, 주소, 기준 지점, 상품별 재고)이 나온다. 지역(전체/서울/수원/판교)으로 좁힐 수 있다.
  4. 점포를 누르면 그 점포 바로 아래에 **지도**가 펼쳐진다. 다시 누르면 접힌다.
- **지도:** 오픈스트리트맵을 `iframe`으로 끼워 넣는다(키·가입·라이브러리 불필요). 점포를 눌렀을 때만 불러온다. 길찾기용 "카카오맵에서 열기" 링크를 함께 둔다.
- **`data.json` 구조 변경** (4번을 대신한다): 지도를 그리려면 점포 좌표가 필요하므로 점포 단위로 저장한다.

```json
{
  "fetchedAt": "2026-10-11T20:30:00+09:00",
  "source": "재고조회 MCP (각 편의점 앱 데이터 기반, 비공식)",
  "areas": [{ "id": "gangnam", "region": "서울", "name": "강남역", "lat": 37.4979, "lng": 127.0276 }],
  "chains": [
    { "id": "cu", "name": "CU", "status": "ok", "note": "" },
    { "id": "gs25", "name": "GS25", "status": "excluded", "note": "카드 팩 미취급" }
  ],
  "products": [{ "id": "cu-8800286279372", "chain": "cu", "name": "포켓몬)닌자스피너카드", "price": 1000 }],
  "stores": [
    {
      "chain": "cu", "areaId": "gangnam", "name": "강남푸르지오점",
      "address": "서울특별시 강남구 테헤란로4길 6", "lat": 37.49783, "lng": 127.029363, "distanceM": 156,
      "stock": { "cu-8800286279372": 0 }
    }
  ]
}
```

  - `stock`의 값은 숫자(0은 품절) 또는 `null`(확인불가)이다. 둘을 섞지 않는다.
  - `chains[].status`: `ok` / `unknown`(응답 뜻 불분명) / `failed`(도구 실패) / `excluded`(조회 대상 아님).
  - 전화번호는 저장하지 않는다. 지점당 가까운 순 20곳까지 저장한다.
- **화면 여는 방법:** `data.json`을 유지하고, 미리보기 서버나 배포 주소로 확인한다.

## 1. 앱 소개

**한 줄 소개:** 서울·수원·판교의 기준 지점 주변 편의점에 포켓몬 카드가 남아 있는지, Claude가 미리 조회해 둔 결과를 한 화면에서 보는 미니 웹앱.

사용자가 화면에서 할 수 있는 일:

- 지역(서울 / 수원 / 판교)과 기준 지점(예: 강남역)을 고른다.
- 편의점 체인(CU / GS25 / 세븐일레븐 / 이마트24)을 골라 본다.
- 상품(카드 팩 종류)을 고른다.
- "재고 있는 점포만 보기"를 켜고 끈다.
- 점포별 재고 수량, 주소, 기준 지점에서의 거리를 본다.
- 화면 맨 위에서 "이 정보가 언제 조회된 것인지"(조회 기준 시각)를 확인한다.

이 앱은 실시간이 아니다. 웹페이지는 재고조회 도구(MCP)를 직접 부를 수 없어서, Claude가 조회한 결과를 `data.json` 파일에 저장해 두고 웹앱은 그 파일만 읽는다.

## 2. 탐색 호출 결과 (2026-10-11, 총 20회 사용)

### 요약 표

| 체인 | 포켓몬 카드 상품 검색 | 점포 찾기 | 점포별 재고 수량 | 판정 |
|---|---|---|---|---|
| CU | 됨. "포켓몬 카드"로 59개 상품 | 됨. 좌표 또는 지역 키워드 | 됨. 점포마다 `stock` 숫자 | **사용 가능** |
| GS25 | 카드 팩은 안 나옴. 포켓몬 교통카드 1종과 빵·과자만 나옴 | 됨. 좌표 권장 | 형식은 됨(`realStockQuantity`, `isSoldOut`). 대상 상품이 교통카드뿐 | **부분 가능 (카드 팩 없음)** |

### CU (5회 호출, 전부 성공)

- 상품: `cu_check_inventory`에 "포켓몬 카드"를 넣으면 상품 59개가 나온다. 확인된 예:
  나이트원더러카드(1,000원), 닌자스피너카드(1,000원), 사이버저지카드(1,000원), 니힐제로카드(1,000원), 어비스아이카드(1,500원), MEGA드림ex카드(5,000원), 카드케이스(5,000원), 이즐 포켓몬랜덤교통카드(5,000원) 등.
- 한 번 호출에 **상품 1개의 재고만** 나온다. 검색 결과의 첫 번째 상품이 자동 선택된다(`selectionReason: first_candidate`). 원하는 상품을 고르려면 검색어를 "포켓몬 닌자스피너카드"처럼 구체적으로 써야 한다. (이 방식으로 3번 모두 원하는 상품이 선택됨)
- 점포 찾기: 좌표(위도·경도)와 지역 키워드(`storeKeyword`) 둘 다 된다. 다만 키워드 "판교역"은 실제 판교역에서 남쪽으로 약 1km 떨어진 곳(백현카페거리)으로 잡혔다. **좌표를 직접 넣는 쪽이 정확하다.**
- 한 번에 나오는 점포 수: 기준 지점 반경 약 1km 안의 점포 전부. 판교 21개, 수원역 28개, 강남역 45개, 홍대입구역 43개. `storeLimit`을 50으로 넣자 43개가 모두 왔다.
- 응답에 들어 있는 값: 점포명, 주소, 전화번호, 위도·경도, 거리(m), 재고 수량(`stock`), 배달·픽업·예약 가능 여부. 상품 쪽에는 상품 코드, 상품명, 가격.
- **주의:** 조회한 4개 상품 × 4개 지점(점포 총 86곳, 일부는 5~10곳만 확인)에서 재고가 전부 0이었다. 재고가 1 이상인 응답은 한 번도 보지 못했다. 진짜 품절인지, 이 도구가 포켓몬 카드 재고를 0으로만 돌려주는지 구분하지 못했다.

### GS25 (5회 호출, 전부 응답은 옴)

- 상품: "포켓몬 카드" 검색 결과 20개 중 포켓몬 상품은 `이즐)포켓몬30주년랜덤(IC칩)` 교통카드 1개뿐이고 나머지는 다른 교통카드다. "포켓몬" 검색 결과 30개는 교통카드 1개와 빵·쿠키·음료다. **트레이딩 카드 팩은 검색되지 않았다.**
- 검색된 모든 상품에 `stockCheckEnabled: false`(재고 확인 미지원 표시)가 붙어 있다. 그래도 재고조회 도구는 응답을 준다.
- 재고 응답: 강남역 기준 점포 50개 중 42개 일치, 재고 있는 점포 0개. 값은 `realStockQuantity`(실재고), `pickupStockQuantity`, `deliveryStockQuantity`, `isSoldOut`(품절 여부), 점포명, 주소, 전화, 좌표, 거리.
- **문제 1:** `gs25_check_inventory`에 `storeKeyword: "수원역"`을 넣었는데 수원이 아니라 강남역 점포가 돌아왔다(`geocodeUsed: false`, `filterRelaxed: true`). 재고조회에서는 **반드시 좌표를 넣어야 한다.** (`gs25_find_nearby_stores`는 "판교역" 키워드를 제대로 좌표로 바꿨다.)
- **문제 2:** `gs25_find_nearby_stores`는 상품을 지정하지 않았는데도 판교알파점에 `realStockQuantity: 4`를 돌려줬다. 어떤 상품의 수량인지 알 수 없으므로 이 값은 쓰지 않는다.

### 세븐일레븐 (5회 호출, 전부 실패)

- `seveneleven_search_products` 2회, `seveneleven_search_stores` 1회, `seveneleven_check_inventory` 2회 모두 같은 오류:
  `CONVENIENCE_RELAY_FAILED` / HTTP 502 / "일시적인 외부 서비스 오류입니다. 잠시 후 재시도해주세요."
- 상품, 점포, 재고 어느 것도 확인하지 못했다. 도구 설명에는 "실시간 재고 API가 제한된 경우에도 상품 정보와 근처 매장 목록을 제공"한다고 적혀 있어, 복구되더라도 수량이 나오지 않을 수 있다.

### 이마트24 (5회 호출, 2회 정상 · 2회 부분 실패 · 1회 중단)

- `emart24_search_products`: "포켓몬 카드" → 0건. "포켓몬" → 403 Forbidden(접근 거부)으로 0건.
- `emart24_check_inventory`에 "포켓몬카드"(붙여 쓰기)를 넣자 상품 10개가 나왔다:
  열풍의아레나(1,000원), 로켓단의영광(1,000원), 메가브레이브(1,000원), 메가심포니아(1,000원), 블랙볼트(2,000원), 화이트플레어(2,000원), 그리고 각 박스 상품(30,000원) 4종.
  "포켓몬"만 넣으면 장난감·캡슐 상품이 먼저 나온다. **띄어쓰기에 따라 결과가 달라진다.**
- 상품마다 고유 코드(`pluCd`, 바코드 번호)가 있어, 코드로 정확한 상품을 지정할 수 있다.
- 점포 찾기: `emart24_find_nearby_stores`에 키워드만 넣은 첫 호출은 중단됨("The operation was aborted"). 시/도(`경기도`)와 구(`성남시 분당구`)를 함께 넣은 두 번째 호출은 성공(판교 10개 점포). 응답에 점포명, 주소, 전화, 좌표, 영업시간, 24시간 여부가 있다.
- **재고는 확인 못 함:** 재고조회 두 번 모두 `inventory.stores`가 빈 목록(`count: 0`)이었다. "재고 있는 점포가 없다"는 뜻인지 "조회가 안 됐다"는 뜻인지 응답만으로는 알 수 없다.
- **이상한 점:** 강남역 좌표를 넣었는데 가장 가까운 점포가 1.9km 떨어진 곳으로 나왔다(전체 5,656개 중 5개). 가까운 순 정렬이 제대로 되는지 의심스럽다. 좌표 대신 시/도+구 이름이나 `storeKeyword`로 좁히는 편이 안전해 보인다.

### 도구 결과 안의 지시문

도구 응답이나 읽은 파일에서 Claude에게 무언가를 시키는 문장은 발견되지 않았다. (GS25 응답의 "재고 확인 시 itemCode를 전달하면…"은 도구 사용 안내문이다.)

## 3. 조회 범위 제안

호출 횟수 계산 규칙(탐색으로 확인한 것): **기준 지점 1곳 × 상품 1개 = 1회 호출.** 한 번에 그 지점 주변 점포 여러 곳이 함께 나온다. `data.json`에는 지점당 가까운 순 20곳까지만 저장한다.

기준 지점 좌표(공개된 역 위치):

| 지역 | 기준 지점 | 위도, 경도 |
|---|---|---|
| 서울 | 강남역 | 37.4979, 127.0276 |
| 서울 | 홍대입구역 | 37.5572, 126.9245 |
| 서울 | 서울역 | 37.5547, 126.9707 |
| 수원 | 수원역 | 37.2660, 127.0000 |
| 판교 | 판교역 | 37.3948, 127.1112 |

### 안 A: 최소 (CU 중심) — 총 9회

- 지점 3곳: 강남역, 수원역, 판교역
- CU 상품 2종 × 3곳 = 6회
- 이마트24 상품 1종 × 3곳 = 3회
- GS25, 세븐일레븐은 조회하지 않고 화면에 "조회 불가"로 표시
- 장점: 빠르고 단순. 단점: 서울이 강남역 한 곳뿐.

### 안 B: 추천 — 총 31회 (세븐일레븐 복구 시 최대 42회)

- 지점 5곳: 위 표 전부
- CU 상품 3종 × 5곳 = 15회
- 이마트24 상품 2종 × 5곳 = 10회
- GS25 교통카드 1종 × 5곳 = 5회
- 세븐일레븐 복구 확인 1회. 복구돼 있으면 상품 검색 1회 + 상품 2종 × 5곳 = 11회 추가
- 합계: 15 + 10 + 5 + 1 = **31회**, 세븐일레븐 포함 시 15 + 10 + 5 + 1 + 11 = **42회**

### 안 C: 넓게 — 총 98회

- 지점 8곳: 서울 6곳(강남역, 홍대입구역, 서울역, 잠실역, 신촌역, 건대입구역) + 수원역 + 판교역
- CU 5종 + 이마트24 3종 + GS25 1종 + 세븐일레븐 3종 = 지점당 12회 × 8곳 = 96회
- 상품 검색 2회 추가 → **98회**
- 단점: 갱신할 때마다 시간이 오래 걸리고, 중간에 도구가 실패할 가능성이 커진다.

추천은 **안 B**다. 처음 만들 때는 안 A로 시작해 화면을 완성한 뒤 지점을 늘려도 된다.

## 4. `data.json` 구조

JSON은 "이름: 값" 짝으로 데이터를 적는 텍스트 형식이다. 아래 예시의 CU 값은 탐색 호출에서 실제로 받은 값이다.

```json
{
  "fetchedAt": "2026-10-11T20:30:00+09:00",
  "source": "재고조회 MCP (각 편의점 앱 데이터 기반)",
  "areas": [
    { "id": "pangyo", "region": "판교", "name": "판교역", "lat": 37.3948, "lng": 127.1112 }
  ],
  "chains": [
    { "id": "cu", "name": "CU", "status": "ok", "note": "" },
    { "id": "gs25", "name": "GS25", "status": "partial", "note": "카드 팩은 검색되지 않아 포켓몬 교통카드만 조회" },
    { "id": "seveneleven", "name": "세븐일레븐", "status": "failed", "note": "조회 도구 오류(502)로 확인 불가" },
    { "id": "emart24", "name": "이마트24", "status": "unknown", "note": "재고 수량 응답이 비어 있음" }
  ],
  "products": [
    { "id": "cu-8800286279372", "chain": "cu", "name": "포켓몬)닌자스피너카드", "price": 1000 }
  ],
  "stocks": [
    {
      "chain": "cu",
      "areaId": "pangyo",
      "productId": "cu-8800286279372",
      "storeName": "백현카페거리점",
      "address": "경기도 성남시 분당구 판교역로50번길 30, (백현동)",
      "distanceM": 3,
      "stock": 0
    }
  ]
}
```

각 값의 뜻:

- `fetchedAt`: 조회 기준 시각. 화면 맨 위에 그대로 보여 준다.
- `chains[].status`: `ok`(정상), `partial`(일부만), `failed`(도구 실패), `unknown`(응답은 왔지만 뜻이 불분명). `ok`가 아니면 화면에 `note`를 함께 보여 준다.
- `stocks[].stock`: **숫자면 재고 수량**(0은 품절), **`null`이면 확인 불가.** 0과 null을 섞지 않는다. 확인하지 못한 것을 품절로 보여 주면 틀린 정보가 되기 때문이다.
- 전화번호는 저장하지 않는다(화면에 필요 없고, 응답에 개인 휴대폰 번호로 보이는 값이 섞여 있다).

## 5. 파일 구조

```
샘플 블로그/apps/pokemon-stock/
├── index.html            화면의 뼈대 (제목, 필터 버튼, 결과가 들어갈 빈 자리)
├── style.css             색·크기·배치. 블로그와 같은 검정 배경 + 네온 색
├── script.js             data.json을 읽어 와 필터에 맞는 점포만 화면에 그림
├── data.json             Claude가 조회한 재고 결과 (웹앱은 읽기만 함)
├── Spec.md               이 계획서
├── plan-instructions.md  Plan 단계 지침 (이미 있음)
└── review.md             Review 단계에서 작성
```

- 외부 라이브러리(CDN)는 쓰지 않는다. 필터와 목록 그리기는 기본 JavaScript로 충분하다.
- 블로그의 색을 맞추기 위해 블로그 `style.css`의 색 변수(`--bg`, `--main`, `--point`, `--sub`) 값을 앱의 `style.css`에 **복사**한다. 블로그 파일을 불러오거나 고치지 않는다(자체 완결 규칙).
- **알아 둘 점:** `script.js`가 `data.json`을 읽는 방법(`fetch`)은 파일을 더블클릭해 연 화면(`file://`)에서는 브라우저가 막는다. 미리보기 서버로 열거나 배포된 주소에서 봐야 한다. (9번 질문 5 참고)

## 7. 재고 갱신 절차

사용자가 "재고 다시 조회해줘"라고 하면 Claude가 다음을 한다.

1. 승인된 조회 범위(지점·상품 목록)와 예상 호출 횟수를 먼저 알려 준다.
2. 체인별로 조회한다. 입력에는 상품 검색어와 공개 좌표·지역명만 넣는다.
   - CU: `cu_check_inventory`에 구체적인 상품명 + 좌표
   - GS25: `gs25_check_inventory`에 상품 코드(`itemCode`) + 좌표 (지역 키워드는 쓰지 않음)
   - 이마트24: `emart24_check_inventory`에 상품 코드(`pluCd`) + 지역 조건
   - 세븐일레븐: 먼저 1회 호출해 복구됐는지 확인하고, 실패하면 건너뜀
3. 응답의 선택된 상품명이 요청한 상품과 같은지 확인한다. 다르면 그 결과는 버린다.
4. 실패한 호출은 1번만 다시 시도한다. 그래도 실패하면 그 체인의 `status`를 `failed`로, 해당 재고를 `null`로 적는다. 이전 값을 남겨 두거나 추측으로 채우지 않는다.
5. `data.json`을 통째로 새로 쓰고 `fetchedAt`을 현재 시각으로 바꾼다.
6. 사용자에게 보고한다: 체인별 성공·실패, 재고가 있는 점포 수, 총 호출 횟수.

깃 커밋과 배포는 사용자가 따로 요청할 때만 한다.

## 8. 한계와 위험

- **실시간이 아니다.** 조회한 순간의 값이다. 포켓몬 카드는 금방 팔리므로 화면에 조회 기준 시각과 "방문 전 점포에 확인하세요"를 항상 보여 준다.
- **CU 재고가 전부 0으로 나왔다.** 86개 점포에서 4개 상품 모두 0이었다. 실제 품절일 수도 있고, 도구가 이 상품군의 재고를 제대로 못 가져오는 것일 수도 있다. 앱이 "전부 품절"만 보여 주게 될 수 있다.
- **GS25에는 카드 팩이 없다.** 조회되는 것은 포켓몬 그림 교통카드다. "포켓몬 카드"라는 앱 이름과 맞는지 사용자가 정해야 한다.
- **세븐일레븐은 지금 조회되지 않는다.** 복구 시점을 알 수 없다.
- **이마트24 재고 수량은 미확인.** 빈 응답의 뜻을 모르므로 지금은 `null`(확인불가)로 표시해야 한다.
- **검색어에 민감하다.** "포켓몬 카드"와 "포켓몬카드"의 결과가 다르고, 첫 번째 검색 결과가 자동 선택된다. 엉뚱한 상품의 재고를 저장하지 않도록 상품 코드와 상품명을 매번 확인한다.
- **범위가 좁다.** 기준 지점 반경 약 1km만 본다. "서울 전체"가 아니라는 점을 화면에 적는다.
- **데이터 출처 표시.** 화면 아래에 출처(재고조회 MCP, 각 편의점 앱 데이터 기반)와 비공식 조회 결과임을 적는다.
- **상품 사진은 쓰지 않는다.** 응답에 이미지 주소가 있지만 편의점 서버의 이미지를 가져다 쓰는 것은 권리 문제와 링크 끊김 위험이 있다.

사용자가 고른 기능 5개(즐겨찾기 점포, 오늘 조회 횟수, 카드 검색, 팩별 힛카드 시세 요약, 시세순 정렬)의 기획과 작업 순서.
새 외부 서비스는 쓰지 않는다(재고는 기존 공개 재고조회 서버, 시세는 기존 TCGdex + Frankfurter 환율).
기록은 모두 이 브라우저(localStorage)에만 저장하고 밖으로 보내지 않는다.

### 10-1. 즐겨찾기 점포 (기획 3번) — 제외
- **화면**: 결과 목록의 점포마다 오른쪽에 ☆ 버튼. 누르면 ★(즐겨찾기)로 바뀌고 다시 누르면 풀린다. 즐겨찾기 점포는 목록에서 맨 위에 온다.
- **조회**: 사이드바 "조회할 권역" 위에 `☐ 즐겨찾기 점포만 조회 (N곳)` 체크박스. 체크하면 권역 선택이 잠기고, 즐겨찾기 점포만 그 점포 좌표(세븐일레븐은 점포 이름)로 한 번씩 조회한다.
  - [재고 조회]와 [일괄 조회] 둘 다 적용된다. 일괄 조회는 즐겨찾기 수 × 팩 15개.
  - 조회 횟수가 크게 준다(예: 즐겨찾기 5곳 → 재고 조회 5회, 일괄 조회 75회).
- **저장**: `pokemon-stock-favs` = ["cu:12345", ...]. 편의점 체크는 그대로 적용(체크 안 한 편의점의 즐겨찾기는 건너뜀).

### 10-2. 오늘 조회 횟수 (기획 4번) — 제외
- **표시**: 사이드바 예상 조회 문구 아래 `오늘 이 브라우저에서 조회 123회 · 공개 서버 하루 한도 약 3,000회`. 2,500회를 넘으면 빨간색.
- **세는 방법**: 재고조회 서버를 부를 때마다(연결 상태 확인·재고·네이버 지도 포함) 1씩 더한다. 날짜(한국 시간)가 바뀌면 0부터.
- **일괄 조회 확인 창**: "오늘 이미 123회 사용, 이번 조회 후 약 1,823회"를 함께 보여 준다.
- **한계**: 서버 한도는 인터넷 주소(IP) 기준이라, 같은 와이파이의 다른 기기·다른 브라우저 사용량은 셀 수 없다.

### 10-3. 카드 검색 (기획 6번)
- **화면**: 카드 조회 화면 맨 위에 검색칸 `카드 이름 검색 (예: 피카츄, 뮤츠)`. [카드 조회]는 팩을 고르지 않아도 열 수 있게 바꾸고, 그때는 검색칸만 보인다.
- **검색 범위**: 16개 팩 전체 카드 2,255장의 한국어 이름·원래(일본어·영어) 이름·포켓몬 이름. 띄어쓰기·대소문자 무시.
- **결과**: 그림 격자. 카드 아래에 `팩 이름 · 번호 · 등급`. 누르면 기존 카드 창(큰 그림 + 원화 시세). 결과가 200장을 넘으면 앞 200장만 보여 주고 더 구체적으로 적으라고 안내.
- **서버 호출**: 없음(이미 받은 cards.json에서 찾는다).

### 10-4. 팩별 힛카드 시세 요약 (기획 7번)
- **화면**: 카드 조회의 팩 정보 줄 아래에 시세 요약 칸.
  - `힛카드 시세 ₩12,000 ~ ₩399,400 · 평균 ₩85,000`
  - `비싼 카드 TOP 3`: 작은 그림 + 이름 + 원화 시세(누르면 카드 창).
- **불러오기**: 팩 화면이 열릴 때 그 팩의 힛카드 시세를 자동으로 불러온다(팩당 7~18회, 3개씩 동시에). 등급 자료가 없는 팩은 펼쳐 보이는 8장 기준. 이미 불러온 시세는 다시 부르지 않는다.
- **표시 기준**: 기존 카드 창과 같다(일본어판 시세 → 없으면 같은 그림의 영어판 시세, 그날 환율로 원화). 시세가 없는 카드는 범위에서 뺀다.

### 10-5. 시세순 정렬 (기획 8번)
- **화면**: "전체 카드 보기"를 펼치면 위에 `[번호순] [시세순]` 버튼.
- **시세순을 누르면**: 그 팩의 모든 카드 시세를 불러온 뒤(진행 표시 `시세 불러오는 중 45/117`) 비싼 순으로 다시 놓고, 카드마다 이름 아래에 원화 시세를 적는다. 시세가 없는 카드는 맨 뒤.
- **서버 호출**: 팩당 92~250회(TCGdex). 누를 때만 부르고, 한 번 불러온 팩은 다시 부르지 않는다. 버튼 옆에 "카드 ○장의 시세를 불러옵니다"를 적어 둔다.

### 10-6. 작업 순서와 확인
| 순서 | 작업 | 고칠 파일 | 확인 방법 |
|---|---|---|---|
| 1 | 오늘 조회 횟수 | script.js, index.html | 연결 상태 확인 4회가 세어지는지, 날짜가 바뀌면 0이 되는지 |
| 2 | 카드 검색 | script.js, style.css, index.html | "피카츄"·"뮤츠"·일본어 이름 검색 결과, 카드 창 열림 |
| 3 | 즐겨찾기 점포 | script.js, style.css, index.html | 점포 2~3곳 즐겨찾기 후 즐겨찾기 조회(서버 호출 몇 회), 권역 잠김 |
| 4 | 팩별 힛카드 시세 요약 | script.js, style.css | 시세가 있는 팩·없는 팩, TOP 3 누르면 카드 창 |
| 5 | 시세순 정렬 | script.js, style.css | 한 팩 시세순 정렬, 진행 표시, 다시 번호순 |
| 6 | 마무리 | CLAUDE.md, 버전 28 | 넓은 화면·휴대폰, 콘솔 오류 없음 → 커밋·배포(요청 시) |

- 1~3은 서로 독립, 4·5는 "여러 카드 시세를 한꺼번에 불러오기"를 함께 쓴다.
- 확인에 쓰는 서버 호출: 재고조회 서버 약 10회, TCGdex 약 300회.

## 11. 추가 기능·디자인 계획 2차 (2026-10-18 작성, 2026-10-18 사용자 승인)

사용자가 고른 기능 A·B·C와 디자인 1~7의 기획과 작업 순서. 새 외부 서비스는 쓰지 않는다.
기존 결정(버튼 배치, 편의점 연결 상태 4칸 한 줄 등)은 아래에서 바꾸는 부분만 바꾼다.

### 11-A. 시세 오름·내림 표시
- **기준**: 받아 오는 시세의 7일 평균과 30일 평균을 비교한다. (7일 - 30일) ÷ 30일. ±3% 안이면 "보합", 그 밖이면 ▲12%(빨강)·▼5%(파랑). 30일 평균이 없으면 표시하지 않는다.
- **표시 위치**: 카드 창(평균 거래가 옆), 시세를 불러온 카드 칸(시세 옆), 팩의 힛카드 시세 요약에 "최근 오른 힛카드 TOP 3" 한 줄 추가.
- **서버 호출**: 늘지 않는다(이미 받는 시세에 들어 있음).

### 11-B. 팩 개봉 시뮬레이터 (재미용)
- **화면**: 팩 화면의 [팩 열기] 옆에 [가상 개봉] 버튼. 누르면 카드 5장이 한 장씩 뒤집히며 나오고, 다 나오면 "이번 팩 시세 합계 약 ₩8,300"과 [한 팩 더] 버튼.
- **카드 구성(대략, 공식 확률 아님)**: 1~3번째 커먼/언커먼, 4번째 언커먼, 5번째 "레어 칸"에서 등급을 뽑는다
  (R 55%, RR 20%, AR 15%, SR 6%, SAR 3%, UR·MUR·BWR·FR 1%. 그 팩에 없는 등급은 빼고 나머지 비율로 다시 나눈다).
  화면에 "실제 확률이 아닌 재미용 대략 확률"이라고 적는다.
- **쓸 수 있는 팩**: 카드 등급 자료가 다 있는 11개 팩(30주년, 어비스아이, 닌자스피너, 니힐제로, 인페르노X, 메가브레이브, 메가심포니아, 블랙볼트, 화이트플레어, 로켓단의 영광, 초전브레이커).
  등급 자료가 없는 팩과 구성이 다른 하이클래스팩(스톰에메랄다, MEGA 드림 ex, 열풍의 아레나, 배틀파트너즈, 테라스탈 페스타 ex)은 버튼 대신 "등급 자료가 없어 가상 개봉을 할 수 없습니다".
- **서버 호출**: 한 팩에 5회(나온 카드 시세). 같은 카드는 다시 부르지 않는다.
- **움직임**: 기기의 "동작 줄이기" 설정이면 뒤집기 없이 바로 보여 준다.

### 11-C. 조회 결과 공유
- **화면**: 재고 결과 목록 제목 옆에 [결과 공유] 버튼(조회가 끝난 뒤에만).
- **내용**: 지금 목록에 보이는 점포(편의점 카드로 좁혔거나 점포 검색 중이면 그 결과) 중 위에서 10곳.
  "포켓몬 카드 재고 · 10/18 20:31 조회 / 어비스아이 · 서울 중구 / CU 명동역점 재고 3 · 서울 중구 … / (사이트 주소)"
- **보내는 법**: 휴대폰은 기본 공유 창(카카오톡·문자 등 선택), 공유 창이 없는 PC는 글을 복사하고 "복사했습니다" 표시.
  내 위치(거리)는 넣지 않는다.

## 12. 첫 화면 포켓몬 카드 소식 게시판 (2026-10-18, 사용자가 ③ 실시간 방식 선택)

- **왜 중계가 필요한가**: 포켓몬코리아 사이트(pokemoncard.co.kr)는 다른 사이트의 읽기를 허용하지 않아(CORS 없음) 방문자 브라우저가 직접 읽을 수 없다. 서버 쪽에서는 읽힌다.
- **중계 프로그램**: Cloudflare Worker(무료) 하나. 코드는 프로젝트의 `cloudflare-worker/news-worker.js`(배포 폴더 밖)에 두고, 사용자가 Cloudflare 대시보드에서 Worker를 만들어 붙여 넣는다.
  - 읽는 곳(고정 주소만): 새소식 목록(`/v3/news_ajax`, 카드 게임 분류), 확장팩 목록(`/card/category/info1`), 스타터·세트 목록(`/card/category/info2`), 최신 제품 상세 몇 개(발매일·가격).
  - 30분 동안은 받아 둔 자료를 다시 쓴다(공식 사이트 부담 줄이기). 방문자 입력을 받지 않으므로 다른 주소를 대신 읽는 데 쓰일 수 없다.
  - 돌려주는 자료: `{ fetchedAt, news: [{ title, category, date, url, image, isNew }], products: [{ name, url, image, releaseDate, price }] }`
- **첫 화면 게시판**(안내 아래, 첫 화면에서만 보임):
  - 새소식 10개(더보기로 20개): 날짜 · 분류 배지(대회·이벤트·발매·매장·공지, 제목 낱말로 자동 분류) · 제목(누르면 공식 사이트 글, 새 탭) · NEW.
  - 최근·발매 예정 제품 4~6개: 팩 그림, 제품명, 발매일, 가격, 앞으로 나올 제품은 D-day.
  - "○월 ○일 ○시 기준 · 출처 포켓몬코리아". 중계를 못 부르면 "소식을 불러오지 못했습니다 · 공식 사이트에서 보기" 링크만.
  - 중계 주소가 아직 없으면 게시판을 숨긴다.
- **안전**: 공식 사이트에서 온 글은 글자(textContent)로만 넣고, 링크·그림 주소는 포켓몬코리아 주소인지 확인한 뒤에만 쓴다.
- **확인**: Worker 코드를 이 맥에서 node 로 돌려(공식 사이트 약 9회 호출) 게시판을 로컬에서 시험한 뒤, 사용자가 만든 Worker 주소를 넣는다.

## 13. 카드 시세 탭 (2026-10-22 분석·기획, 승인 대기)

### 13-1. 참고 사이트 분석: KREAM 포켓몬 카드 시세표 (content.kream.co.kr/tcg-chart/pokemon)
- **화면 구성(위에서 아래로)**
  1. 게임 탭: 포켓몬 / 원피스
  2. 제목 "포켓몬 카드 시세 Beta" + **등급 칩**: Ungraded 827 · PSA 10 1326 · PSA 9 197 · PSA 8 · BRG 10 · BRG 9 … (숫자 = 그 등급의 카드 수)
  3. 기준 안내: "최근 30일 동안 KREAM에서 거래된 … 시세", 기준일, 차트 기준
  4. **어제 시장 인사이트**: 가격 상승 / 상승 전환 / 거래량 대비 저렴 (누르면 해당 카드 묶음)
  5. **30일 시세·거래량**: 최근 체결가 중앙값(예: 38,293원), 1일·7일·30일 전 대비 %, 30일 총 거래량, 작은 선 그래프
  6. **전일 상승 Top 5**: 순위, 카드 그림, 이름(판 표기), 가격, 상승률, 거래량, 작은 그래프
  7. **카드 시세 목록**: 세부 옵션 칩(전체·Ungraded A·Card Ver.·Pack Ver. + 개수), 정렬(거래순·가격높은순·가격낮은순·급상승순·급하락순), 카드 줄(옵션·판 국가 배지 KR/JP, 이름, 최근 체결가 중앙값, 변동률, 30일 시세 그래프)
  8. 면책 문구(KREAM 거래 자료 기반, 비자문 참고자료)
- **자료가 오는 곳**: KREAM 내부 서버 `api.kream.co.kr/api/data_mart/serving/trading_card`. KREAM 페이지(content.kream.co.kr)에서만 읽도록 막혀 있고(CORS), KREAM 앱 전용 머리글 없이 부르면 오류(500)가 난다. 공개 API가 아니다.
- **판단**: KREAM 자료를 가져오려면 중계 프로그램으로 KREAM 내부 서버를 흉내 내야 한다. 이는 KREAM 이용약관이 보통 금지하는 자동 수집에 해당하고, 언제든 막힐 수 있다. pokeconv.shop 때와 같은 원칙(다른 서비스의 전용 API는 쓰지 않는다)에 따라 **KREAM 자료는 쓰지 않고, 화면 구성·기능만 참고**한다. 카드마다 "KREAM에서 보기" 링크(검색 주소)는 둘 수 있다.

### 13-2. 우리가 쓸 수 있는 시세 자료
- TCGdex 카드 정보의 Cardmarket(유럽 거래 사이트) 거래가: 평균(avg), 최저(low), 추세(trend), 1일·7일·30일 평균(avg1·avg7·avg30). 일본어판·영어판 카드. 원화는 그날 환율(Frankfurter)로 바꾼다.
- 할 수 없는 것: 한국어판(한글판) 카드 시세, PSA·BRG 등급 카드 시세, 거래량(건수), 일별 시세 그래프(30일치 매일 값은 없고 1·7·30일 평균 세 값만 있다).

### 13-3. 기획: 웹앱 본문 위에 탭 [재고·카드] [카드 시세]

|---|---|---|

### 13-4. 시세 자료를 모으는 방법 (정할 것)
- 카드 한 장마다 TCGdex를 한 번씩 불러야 해서, 방문자가 탭을 열 때마다 수백 장을 부를 수는 없다. 미리 모아 `prices.json`(시세 묶음)으로 둔다.
- **대상 카드**: (가) 시크릿 카드 682장(힛카드 103장 포함, 추천) / (나) 전체 2,255장
- **갱신 방법**: (1) 요청할 때 `node build-prices.mjs` 실행 후 배포(추천, 기존 방식과 같음) / (2) Cloudflare Worker 예약 실행으로 매일 자동(무료 등급의 1회 50건 제한 때문에 나눠 모으고 저장소(KV) 설정이 필요해 복잡)

### 13-5. 작업 순서(승인 후)
1. `build-prices.mjs`: 대상 카드의 Cardmarket 시세를 모아 `prices.json` 저장(TCGdex 약 700회, 약 3분)
2. 탭 틀: 본문 위 [재고·카드]/[카드 시세] 탭, 휴대폰에서도 같은 자리
3. 카드 시세 탭: 등급 칩 → 기준 안내 → 인사이트 → 시세 요약 → 상승 Top 5 → 검색·옵션·정렬 → 카드 목록(작은 그래프 포함) → 면책 문구
4. 카드 창에 "KREAM에서 보기" 링크
5. 확인(넓은 화면·휴대폰), CLAUDE.md 기록, 버전 올림

## 14. 거래소 탭과 도감 판매처 지도 (2026-10-22, 사용자 결정)

- 13장(KREAM 자료로 카드 시세 탭)은 하지 않기로 했다.
- **확인**: 포켓몬 카드 도감(www.dogam.app)의 `/market`(거래소)과 `/shops`(판매처 지도)는 `X-Frame-Options: DENY`, `frame-ancestors 'none'`으로 다른 페이지 안에 넣는 것(iframe)을 막는다. 그래서 둘 다 **새 탭으로 연다**.
- **거래소 탭**(사용자 결정: 탭으로): 본문 맨 위에 [재고·카드] / [거래소] 탭. [거래소]에는 소개와 [거래소 열기 ↗](https://www.dogam.app/market, 새 탭). 조회 버튼을 누르면 [재고·카드] 탭으로 돌아간다.
- **네이버 지도**(사용자 결정: 도감 지도로 변경): "내 주변 판매처 찾기"를 체크하고 [재고 조회]를 누르면 `https://www.dogam.app/shops#c=경도,위도,확대단계&k=stock`을 새 탭으로 연다. 확대 단계는 반경 약 10km가 보이도록 넓은 화면 12, 휴대폰 11.
  - 위치(사용자 결정: 약 1km 단위로 흐리게): 위도·경도를 소수 둘째 자리로 반올림해 넘긴다. 위치를 못 받으면 좌표 없이 연다.
  - 위치를 묻는 동안 브라우저가 새 탭을 막지 않도록, 누르자마자 빈 탭을 먼저 열고 위치를 받은 뒤 주소를 넣는다.
  - 예전의 자체 판매처 지도(네이버 지역 검색 `places_search_nearby` + Leaflet·오픈스트리트맵 지도, 무인문구점 함께 찾기)는 지운다. 되살리려면 이 변경 이전 커밋에서 해당 코드를 가져온다.
