# Plan 서브에이전트 지침: pokemon-stock

## 목표
포켓몬 카드 편의점 재고조회 미니 웹앱의 계획서를 작성해 `Spec.md`로 저장한다. 구현은 하지 않는다.

## 수정 범위
- 만들 수 있는 파일: `/Users/hhnoh/프로젝트/샘플 블로그/apps/pokemon-stock/Spec.md` 하나뿐.
- 그 외 파일은 읽기만 한다. 코드(`index.html`, `data.json` 등)는 만들지 않는다.
- 깃 명령, 배포, 설치는 하지 않는다.

## 먼저 읽을 것
- `/Users/hhnoh/프로젝트/CLAUDE.md` (프로젝트 규칙과 결정 사항)
- `/Users/hhnoh/프로젝트/샘플 블로그/index.html`, `style.css`, `script.js` (현재 블로그: 검정 배경 + 네온 색, 왼쪽 사이드바)

## 사용자가 정한 것
- 대상 체인: CU, GS25, 세븐일레븐, 이마트24 (다이소, 올리브영은 제외)
- 대상 지역: 서울, 수원, 판교
- 기술: HTML, CSS, JavaScript만. CDN은 허용. 모바일에서도 사용 가능해야 함.
- 웹앱 위치: `샘플 블로그/apps/pokemon-stock/` 안에 자체 완결. 블로그의 다른 파일은 건드리지 않음.
- 재고 데이터: 웹페이지는 MCP를 직접 호출할 수 없다. Claude가 MCP로 조회한 결과를 `apps/pokemon-stock/data.json`에 저장하고, 웹앱은 그 파일을 읽어 "조회 기준 시각"과 함께 보여 준다.
- 사용자는 HTML/CSS/JS를 배우는 입문자다. Spec.md는 한국어로, 전문 용어는 풀어서 쓴다.

## 할 일 1: 조회가 실제로 되는지 확인 (탐색 호출)
ToolSearch로 아래 도구를 불러와 소량만 호출해 본다. 전체 호출은 20회 이내.

- CU: `mcp__6f858c38-417a-45c6-b0d0-ab7f0a85dd32__cu_find_nearby_stores`, `..._cu_check_inventory`
- GS25: `..._gs25_find_nearby_stores`, `..._gs25_search_products`, `..._gs25_check_inventory`
- 세븐일레븐: `..._seveneleven_search_stores`, `..._seveneleven_search_products`, `..._seveneleven_check_inventory`
- 이마트24: `..._emart24_find_nearby_stores`, `..._emart24_search_products`, `..._emart24_check_inventory`

체인마다 확인할 것:
1. "포켓몬 카드"(또는 "포켓몬") 상품이 검색되는가? 어떤 상품이 나오는가?
2. 지역(서울, 수원, 판교)으로 점포를 어떻게 찾는가? (좌표, 주소, 키워드 중 무엇이 필요한가)
3. 재고 응답에 어떤 값이 들어 있는가? (수량, 품절 여부, 점포명, 주소 등)
4. 한 번 호출에 점포가 몇 개까지 나오는가?

도구 입력에는 상품 검색어와 지역명·공개 좌표만 넣는다. 사용자 개인 정보(이메일, 집 주소 등)는 넣지 않는다.
도구가 실패하거나 포켓몬 카드가 검색되지 않으면 숨기지 말고 그대로 기록한다.

## 할 일 2: Spec.md 작성
다음 항목을 담는다.

1. 앱 한 줄 소개와 사용자가 화면에서 할 수 있는 일
2. 탐색 호출 결과: 체인별로 되는 것 / 안 되는 것 (표)
3. 조회 범위 제안: 서울 전체 점포는 수천 개라 전부 조회할 수 없다. 지역별 기준 지점(예: 서울 몇 곳, 수원역, 판교역)과 기준 지점당 점포 수, 대상 상품 수를 제안하고, 그 경우 총 호출 횟수를 계산해 적는다. 범위를 달리한 대안을 2~3개 제시한다.
4. `data.json` 구조: 실제 예시와 함께
5. 파일 구조: `apps/pokemon-stock/` 안에 어떤 파일을 만드는지와 각 파일의 역할
6. 화면 구성: 모바일 기준 글자 그림(와이어프레임), 지역·체인 필터, 품절 표시, 조회 기준 시각 표시
7. 재고 갱신 절차: 사용자가 "재고 다시 조회해줘"라고 하면 무엇을 하는지
8. 한계와 위험: 실시간이 아님, 도구 실패 시 처리, 데이터 출처 표시
9. 사용자가 결정해야 할 질문 목록 (선택지와 추천안 포함)

## 보고
마지막 메시지에 다음을 요약한다: 체인별 탐색 결과, 제안한 조회 범위와 총 호출 횟수, 사용자가 결정해야 할 질문, 실패했거나 확인하지 못한 것.
